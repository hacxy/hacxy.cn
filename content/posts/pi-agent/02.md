pi agent 的日常工作流是「读 → 改 → 提交」：先阅读相关源码，再动手修改，最后以可审阅的 git 提交落地。这条循环保证了所有变更都可追溯、可回滚。

本文与 `01.md` 同处 `content/posts/pi-agent/` 目录，用于验证上一篇/下一篇只在同目录内按日期倒序相邻、目录边界处停止（不跨界跳转到根层文章）。

## 目录边界

同目录相邻的契约：目录内最新文章无上一篇、最旧文章无下一篇；不同目录的文章互不参与彼此的上一篇/下一篇链。
