# 从 PRD 到计划

使用垂直切片（曳光弹，tracer bullets）把 PRD 拆解为分阶段实现计划。输出是 `./plans/` 下的 Markdown 文件。

## 流程

### 1. 确认 PRD 在上下文中

PRD 应该已经在对话中。如果没有，请用户粘贴它或指出文件位置。

### 2. 探索代码库

如果你还没有探索过代码库，先这样做，以理解当前的架构、现有模式和集成层。

### 3. 识别持久性架构决策

在切片之前，识别贯穿整个实现过程不太可能改变的高层决策：

- 路由结构 / URL 模式
- 数据库结构（schema）
- 关键数据模型
- 认证 / 授权方案
- 第三方服务边界

这些放入计划头部，以便每个阶段都能引用它们。

### 4. 起草垂直切片

把 PRD 拆解为**曳光弹（tracer bullet）**阶段。每个阶段都是一个贯穿**所有**集成层的端到端薄垂直切片，而**不是**单一层的水平切片。

<vertical-slice-rules>
- 每个切片交付一条窄但**完整**的路径，穿过每一层（数据结构、接口、界面、测试）
- 一个完成的切片本身就可演示或可验证
- 宁可要许多薄切片，也不要几个厚切片
- **不要**包含很可能在后续阶段构建时发生变化的特定文件名、函数名或实现细节
- **要**包含持久性决策：路由路径、数据结构形态、数据模型名称
</vertical-slice-rules>

### 5. 询问用户

把提议的拆解呈现为编号列表。对每个阶段展示：

- **标题**：简短的描述性名称
- **覆盖的用户故事**：该阶段覆盖 PRD 中的哪些用户故事

询问用户：

- 粒度感觉合适吗？（太粗 / 太细）
- 是否有任何阶段应该合并或进一步拆分？

迭代直到用户批准该拆解。

### 6. 写入计划文件

如果 `./plans/` 不存在则创建它。以功能命名的 Markdown 文件写入计划（例如 `./plans/user-onboarding.md`）。使用下面的模板。

<plan-template>
# 计划：<功能名称>

> 来源 PRD：<简短标识符或链接>

## 架构决策

适用于所有阶段的持久性决策：

- **路由**：...
- **数据结构**：...
- **关键模型**：...
- （按需添加/移除小节）

---

## 阶段 1：<标题>

**用户故事**：<来自 PRD 的列表>

### 构建内容

对这个垂直切片的简明描述。描述端到端行为，而不是逐层实现。

### 验收标准

- [ ] 标准 1
- [ ] 标准 2
- [ ] 标准 3

---

## 阶段 2：<标题>

**用户故事**：<来自 PRD 的列表>

### 构建内容

...

### 验收标准

- [ ] ...

<!-- 每个阶段重复 -->
</plan-template>
