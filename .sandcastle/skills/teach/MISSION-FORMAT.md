# MISSION.md 格式

`MISSION.md` 位于工作区根目录。它记录了用户学习这个主题的_原因_。每一个教学决策——接下来教什么、展示哪些资源、设计哪些练习——都应该追溯到这份文档。

## 模板

```md
# 使命：{主题}

## 为什么

{1-3 句话。用户追求的具体现实世界目标。当他们拥有这项技能时，他们的生活或工作会发生什么变化？避免"为了理解 X"这类抽象表述——追问底层的结果。}

## 成功的标志

- {一件用户将能够做到的、具体可观察的事}
- {另一件具体的事}
- {……}

## 约束

- {时间、预算、先前承诺、学习偏好，任何限制方法的东西}

## 范围之外

- {用户明确表示现在不想追求的邻近主题——保护最近发展区}
```

## 规则

- **每个工作区一个使命。** 如果用户想学两个不相关的东西，那就是两个工作区。
- **具体优于抽象。** "十月前跑完半程马拉松"胜过"变得更健康"。"给我的团队交付一个 Rust CLI"胜过"学 Rust"。
- **对模糊性提出质疑。** 如果用户无法说出原因，在写任何东西之前先访谈他们。一个糟糕的使命比没有使命更糟。
- **现实改变时就修订。** 使命会变。当用户的目标变化时，更新这个文件——不要让过时的使命引导未来的会话。
- **保持简短。** 如果 `MISSION.md` 超过一屏，它就不再是指南针，而变成了一份计划。
