# 学习记录格式

学习记录存放在 `./learning-records/` 中，使用顺序编号：`0001-slug.md`、`0002-slug.md` 等。惰性创建该目录——只在写入第一条记录时创建。

它们是 ADR（架构决策记录）在教学中的对应物：它们记录非显而易见的经验教训、关键见解和已陈述的先前知识，这些将引导未来的会话。它们用于计算最近发展区。

## 模板

```md
# {所学或所确立内容的简短标题}

{1-3 句话：学到了什么（或确立了哪些先前知识），以及为什么它对未来的会话很重要。}
```

这就是完整的格式。一条学习记录可以是一个段落。价值在于记录_已经知道这件事_以及_为什么它改变了接下来要教什么_——而不是填写各个部分。

## 可选部分

只有当它们能带来真正的价值时才包含这些。大多数记录不需要它们。

- **Status（状态）** frontmatter（`active | superseded by LR-NNNN`）——当早期的理解被证明是错误的并被取代时很有用。
- **Evidence（证据）**——用户如何展示这种理解（回答的问题、完成的练习、引用的先前经验）。当这种说法可能被重新审视时很有用。
- **Implications（影响）**——这对未来的会话解锁了什么或排除了什么。当影响不显而易见时值得记录。

## 编号

扫描 `./learning-records/` 中现有的最大编号并加一。

## 何时写学习记录

当以下任何情况为真时写一条：

1. **用户展示了对某件不简单的事情的真正理解**——不仅仅是接触过，而是有证据表明他们能正确使用这个概念。这为接下来要教什么设定了新的底线。
2. **用户透露了先前知识**——"我已经知道 X 了。"记录下来，这样未来的会话就不会重复教它。同时记录所声称的_深度_。
3. **一个误解被纠正了**——用户之前相信了错误的东西，现在明白了原因。这些价值很高：它们能预测相关主题未来会出现的绊脚石。
4. **使命因学习而转变**——用户发现自己关心的东西与原来以为的不同。交叉链接到 [[MISSION.md]] 并更新它。

### 哪些_不_算

- 仅仅覆盖过的材料。覆盖不等于学习。等待证据。
- 已经以术语定义的形式简洁地收录在 [[GLOSSARY.md]] 中的任何内容。不要重复。
- 逐会话的活动日志。学习记录不是日记——它们是决策级的见解。

## 取代

当一条较晚的记录与较早的记录矛盾时（用户的理解加深或被纠正），将旧记录标记为 `Status: superseded by LR-NNNN`，而不是删除它。理解如何演变的历史本身就是有用的信号。
