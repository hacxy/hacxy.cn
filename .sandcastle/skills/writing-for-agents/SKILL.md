为 agent 会消费的任何文档——一个 skill、一份 `AGENTS.md` / `CLAUDE.md`、一个由指针到达的文档——提供写作参考。包装不同，写作不变：同样的杠杆让每一份文档都可预测——agent 每次运行走相同的_过程_，而不是产出相同的结果。

当你写的文档是一个 skill 时，先读 [`SKILL-MECHANICS.md`](SKILL-MECHANICS.md)，了解 frontmatter、调用方式的选择和路由 skill。

## 上下文指针

**上下文指针**是 agent 上下文中持有的一个引用：它指明某些上下文之外的材料，并编码了到达它的条件。skill 的 description 就是一个；`AGENTS.md` 中指明某个文档的一行也是同一个东西。决定 agent 何时——以及多可靠地——到达材料的，是指针的_措辞_，而不是它的目标。措辞薄弱的指针背后的必达目标是波动性 bug：先强化措辞，只有当强化失败时才把材料内联。

指针做两件事——说明材料是什么，并列出应该触发到达它的**分支**（分支是文档处理的独立情形，因此不同的运行会走不同的路径）。始终加载的指针的每一个词都在每一轮中付出成本，所以它比正文更该被修剪：

- **把引导词前置**——指针的触发工作就在这里发生。
- **每个分支一个触发词。** 为单个分支换名字的近义词，是把一个分支写了两遍；把它们合并，只保留真正不同的分支。
- **删掉正文已经携带的身份信息。**

## 两种负荷

你添加的每个文档和指针都花费两种预算之一，对应两个观察者——人类和 AI agent：

- **上下文负荷**——始终加载的材料对 agent 窗口的成本：一行 `AGENTS.md`、一个 skill 的 description，任何每轮都待在上下文中的东西，无论是否被触发都在消耗 token 和注意力。
- **认知负荷**——人类付出的成本：存在哪些文档、什么时候取用哪个。人类就是索引。这不是要最小化的成本——它是人类能动性的代价；把它花在人类判断重要之处，在无关之处移除它。

只能通过指针到达的材料，以指针自己那一行的代价逃出上下文负荷；完全没有指针的材料则完全由认知负荷承载。

## 信息层级

文档由两种内容类型构建——**步骤**（agent 执行的有序动作）和**参考**（按需查阅的定义、规则、事实）——它们可以自由混合：全是步骤（一份配方）、全是参考（一份评审的规则，比如本 skill），或两者兼有。核心决策是每一块内容落在**信息层级**的哪一级——这个阶梯按 agent 需要材料的紧迫程度排序：

1. **文件内步骤**——第一级：agent 按顺序做什么。
2. **文件内参考**——按需查阅。通常是一个合理的扁平同级集合（一份评审的每条规则都在同一级）——这是合理的安排，不是坏味道。
3. **外置参考**——被推到单独的文件中，通过上下文指针到达，只在指针触发时加载。范围从同文件夹的兄弟文件，一直到存在于任何地方、任何文档都可以指向的完全外部参考。

往下推得太少，顶层就会臃肿；推得太多，你会藏起 agent 真正需要的材料。这种张力就是整个决策。

**渐进式披露**是沿阶梯向下移动——离开主文件、藏到指针后面——从而让顶层保持易读。它主要不是 token 优化：它是保护层级的方式。分支化是最干净的披露检验：把每个分支都需要的内容内联，把只有部分分支会到达的内容推到指针后面。当文档有步骤时，本该被披露的文件内参考会埋没它们，把对它们的关注变成抛硬币——这是一个波动性杠杆，而不只是可读性杠杆。

**就近放置**是文件内部的配套做法：阶梯决定一块内容_向下多深_，就近放置决定一旦到了那里_旁边放什么_。把概念的定义、规则和注意事项放在同一个标题下，而不是散落各处，这样读起一部分就会带上它的邻居。检验标准：文档读起来应该像为 agent 写的文档——归组的内容读起来是这样；散落的内容则不是。（与重复不同：重复是在两个地方重复同一个含义；散落是把一个含义碎片化到许多处。）

**冗长**是这里的失败模式：文档就是太长了，即使每一行都是有效且唯一的。注意力在多余的内容上被稀释，而每多一行都是多一行要保持相关。解药就是阶梯：把参考披露到指针后面，并按分支或序列拆分，让每条路径只携带它需要的内容。

## 步骤与完成标准

每个步骤都以**完成标准**结束——告诉 agent 工作已完成的条件。两个属性使它成为杠杆：

- **清晰度**——agent 能区分完成与未完成吗？模糊的边界（"understanding reached"）会招来**过早完成**：在真正完成之前就结束步骤，注意力滑向_完成的样子_。仍然可见的前方步骤——**后续步骤**——提供拉力；标准的清晰度是阻力。按顺序防御：**先强化边界**（本地且廉价）；只有当它不可还原地模糊_并且_你观察到匆忙时，才通过拆分序列隐藏后面的步骤——而隐藏只在真正的上下文边界上有效（一次交接或 subagent 派发；内联调用会让后面的步骤留在上下文中，什么也清不掉）。
- **要求强度**——它要求多少。"Every modified model accounted for" 强制彻底的工作，而 "produce a change list" 则不会。要求强度驱动**苦功**——agent 在工作内部所做的挖掘，潜伏在措辞里而不是写成独立的步骤——并且它不受步骤限制："every rule applied" 约束一片扁平的参考，正如 "every step done" 约束一个序列，这就是为什么全参考的文档仍然带着一条穷尽性底线。

最强的标准既可检查又穷尽。

## 何时拆分

把一个文档拆成两个会花费两种负荷之一，所以只在拆分的收益配得上它时才拆：

- **按序列**——当后续步骤诱使 agent 赶完眼前这个步骤时，拆分一连串步骤。让它们保持在视野之外，会在当前任务上驱动更多苦功。当心反面：合并序列会把每个步骤的后续步骤暴露给接下来的内容，招来过早完成。
- **按调用方式**——skill 特有：见 [`SKILL-MECHANICS.md`](SKILL-MECHANICS.md)。

## 引导词

**引导词**是已经存在于模型预训练中的紧凑概念，agent 在运行文档时用它来思考（_lesson_、_fog of war_、_tracer bullets_）。作为 token 重复、而不是作为句子重复，它积累出一个分布式定义，并通过调用模型已经持有的先验，用最少的 token 锚定一整片行为区域。如果你定义得清楚，自己造词也行，但一个造出来的词不会调用任何先验——一个预训练的词免费给出的东西，你要用定义 token 来付；优先使用已有的词。

它双重锚定。在正文中，是_执行_：每次这个词出现，agent 都调用相同的行为；在扁平的参考里，它把注意力聚焦到要找的一类东西上。在指针中，是_调用_：当同一个词存在于你的 prompts、你的文档和你的代码库中时，agent 会把这种共享的语言与材料联系起来，从而更可靠地到达它。

主动寻找用引导词重构的机会。一个在三处展开的三元组，一个花一整句话指向某个想法的指针——每一段都在渴求坍缩成单个 token：

- "fast, deterministic, low-overhead" → _tight_（一个 _tight_ loop）。
- "a loop you believe in" → _red_——一个模糊的门变成二元的可观察状态（bug 出现时 loop 变 _red_，或者不变）。

你赢两次：更少的 token，以及一个更锋利的钩子让 agent 挂住它的思考。假设每份文档都携带着可以被引导词退役的重述——去找出它们。

**否定式**是这个杠杆旁边的失败模式：靠禁止来引导，会把被禁止的行为拖进上下文，让它_更_可用，而不是更不可用。_Don't think of an elephant_，然后满脑子都是大象；否定式是一个微弱的修饰语，被强烈激活的概念会压过它，所以禁令有一半被读成"去做这件事"的指令。给出**正面**的提示——陈述目标行为（"write one-line comments"），让被禁止的表述永远不会被说出。禁令只有在作为无法用正面措辞表达的硬护栏时才有立足之地；即便如此，也要把它与正面目标配对，让注意力落在该做什么上。

## 修剪

- 让每个含义保持**单一事实来源**：一个权威的位置，这样改变行为就是一处编辑。**重复**——同一含义出现在不止一处——会付出维护和 token 的代价，并把含义在阶梯上的地位抬高到超出其真实等级。（这是引导词的意外反面：引导词故意重复 token，绝不重复含义。）
- **环境**也是事实来源——`package.json` 脚本、配置文件、目录布局、`--help` 输出——而重述它的文档就是**缓存**：一次查找的副本，只有当查找很昂贵时才配得上它的负荷。缓存 agent 靠看找不到的东西：未写下来的约定、选择背后的理由、任何配置都不会坦白的坑。把单文件、单命令的查找留给环境，在那里它们不会过时。
- 逐行检查**相关性**：它还与文档所做的事有关吗？一行要么因为从不与任务相关（只是铺陈，或一个应该被外置的分支）而失去相关性，要么因为所描述的行为或世界发生变化而过时。更短的文档更容易保持相关。没有修剪纪律，默认的命运是**沉积**：过时的层不断沉积，因为添加感觉安全、删除感觉冒险，直到你必须穿过它们向下钻取，才能找到仍然鲜活的东西。
- 逐句猎杀**空操作**：一条模型默认已经服从的指令，花费负荷却什么也没说。检验标准——与默认相比它是否改变了行为？——是模型相关的，而不是读者相关的：两个对空操作有分歧的人，分歧在于默认值，并且通过运行文档来裁决，而不是通过辩论。当一个句子不合格时，删除整个句子，而不是从它上面删减几个词。这个检验也用于给引导词打分：一个弱到打不过默认值的词（当 agent 已经差不多 thorough 时还要 _be thorough_）就是空操作，修法是换一个更强的词（_relentless_），而不是换一种技巧。
